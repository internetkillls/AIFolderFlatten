# Codex Implementation Prompt

## Exact Scope

Implement and maintain the AIFolderFlatten v0.2.2 expert-system-only hardening:

- Preserve deterministic local folder scanning, parsing, analysis, rendering, and pack generation.
- Enforce the expert-system boundary in configuration and runtime guards.
- Emit manifest boundary fields and `EXPERT_SYSTEM_PROVENANCE.md` for pack outputs.
- Keep candidate-language outputs clearly labeled as heuristic, non-AI analysis.
- Limit changes to expert-system boundary, provenance, manifest, parser registry, templates, tests, and directly related documentation.

## Forbidden Changes

- Do not add LLM, agent, embedding, inference, telemetry, or cloud API dependencies.
- Do not enable network access in the core pipeline.
- Do not weaken privacy scanning, redaction, manifest verification, or deterministic output behavior.
- Do not describe heuristic output as generated by AI.
- Do not make unrelated UI, installer, or architecture changes.

## Manifest And Provenance Requirements

- `MANIFEST.json` must attest `aiCore=false`, `networkUsed=false`, `llmUsed=false`, `embeddingsUsed=false`, and `expertSystemOnly=true`.
- Pack output must include `EXPERT_SYSTEM_PROVENANCE.md`.
- Provenance must record tool version, source root, parser tiers, external tools, fallbacks, and known limitations.
- Manifest verification must reject a pack whose expert-system attestation is missing or invalid.

## Expert-System-Only Boundary

The core is expert-system-only. It must remain local, deterministic, and free of LLM calls, embeddings, agents, and network access.
